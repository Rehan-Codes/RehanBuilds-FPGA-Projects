# Project 04 — Configurable PWM Generator

**Platform:** Digilent Basys 3 (XC7A35T-1), Vivado 2025.2. FPGA clock: 100 MHz.

## What it does

Creates a PWM digital output at **JA1** (Pmod JA signal 1, FPGA PACKAGE_PIN J1), with adjustable frequency and duty cycle. Configuration is synchronized to the FPGA clock and applied **only at PWM period boundaries**, preventing partial-cycle configuration glitches.

### Controls

| Switches | Setting | Meaning |
|---|---|---|
| SW1:SW0 | 00 / 01 / 10 / 11 | 0% / 25% / 50% / 75% duty cycle |
| SW3:SW2 | 00 / 01 / 10 / 11 | 1 / 2 / 4 / 8 kHz PWM frequency |
| BTNC | Press | Reset PWM phase and reload selected settings; output is LOW while reset is held |
| LD4 | PWM display | Mirrors PWM; LED brightness varies with duty cycle, flicker usually not visible |
| LD3:LD2 | Binary code | Latched frequency selection |
| LD1:LD0 | Binary code | Latched duty selection |

At **all switches OFF**, PWM output is **constant LOW** (0% duty). To see duty activity, turn **SW1 ON** (50%) or **SW0 ON** (25%).

## Files

- `pwm_top.sv` — synthesizable parameterized RTL; 2-FF switch/button synchronizers, period counter, registered boundary-safe settings.
- `tb_pwm_top.sv` — self-checking SystemVerilog testbench for all **16 frequency/duty combinations**, LED correlation, and mid-period configuration update.
- `pwm_basys3.xdc` — official Digilent Basys 3 I/O pins and 100 MHz timing constraint.

## Vivado instructions

1. Create RTL project `video04_pwm` for part `xc7a35tcpg236-1`.
2. Add `pwm_top.sv` to **Design Sources**, `tb_pwm_top.sv` to **Simulation Sources**, and `pwm_basys3.xdc` to **Constraints**.
3. Set `tb_pwm_top` as Simulation Top, run **Behavioral Simulation** then Tcl `run -all` if needed.
4. Wait for the **SUCCESS** line (do not assume success before observing it).
5. Set `pwm_top` as synthesis top, run Synthesis, Implementation, Timing Summary, and Generate Bitstream. Program Basys 3.
6. Test 25%, 50%, 75%, and 0% settings. Use the AD3 to inspect the PWM output.

Expected successful testbench conclusion:
`SUCCESS: Project 04 PWM testbench PASSED (16 configurations, ... comparisons).`

## AD3 measurement — important safety note

- The PWM signal is a **3.3 V digital output**, not an analog variable voltage.
- With both devices properly powered, connect an AD3 *oscilloscope input* to **JA1** and the corresponding scope return/reference to **Basys 3 Pmod GND**. The Pmod's ground pins are **5 and 11**, *not* the neighboring 3.3 V pins 6/12. Verify the physical pin numbering using Digilent's Basys 3 Pmod diagram; do not infer pin numbering from board orientation.
- Configure the AD3 input as a measurement input, never as a driven output into JA1. Do **not** connect AD3 power rails to the FPGA's JA signal or power pins.
- At SW3:SW2=`00`, SW1:SW0=`10`, expect approximately **1 kHz, 50% duty, 0–3.3 V**. This means period ~1 ms, HIGH ~0.5 ms. Changing to 11 should produce 75%; changing frequency selection 10 should produce 4 kHz.
- If you lack a suitable safe probing lead, finish simulation and board verification and note that AD3 physical measurement is pending.

## Scope and limitations

- No PLL or new clocks; PWM generated by a counter clocked at 100 MHz.
- Signal switches are synchronized but not debounced; brief intermediate settings can occur while changing multiple switches. The active selection updates on a period boundary.
- Four fixed frequency choices and four fixed duty choices rather than continuous tuning.
- External asynchronous switch and LED/JA paths do not have external interface input/output-delay constraints; timing report applies to the constrained internal design.
- Tests are designed for selected behaviors and expected output sequences. They are not formal exhaustive verification of all possible switching waveforms.
